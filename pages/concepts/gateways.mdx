# Gateways

Gateways let you serve IPFS content over HTTP. Pinarkive provides cluster-specific HTTPS gateways. Production apps may also use the public IPFS gateway for redundancy; the DEV sandbox and playground use **only** the Pinarkive DEV gateways (no silent `ipfs.io` fallback).

## DEV sandbox gateways

When using the [sandbox API](/concepts/environments) (`https://api-dev.pinarkive.com`), serve content through the matching DEV gateway host on `eu-es-ion-03`:

| Cluster (DEV) | Gateway base |
|---------------|--------------|
| **global** (`cl0-global-dev`) | `https://gateway-dev.pinarkive.com/ipfs/<cid>` |
| **eu** (`cl1-eu-dev`) | `https://eu1-gateway-dev.pinarkive.com/ipfs/<cid>` |
| **es** (`cl2-eu-es-dev`) | `https://es1-gateway-dev.pinarkive.com/ipfs/<cid>` |

If a gateway returns an error (for example while nginx is being updated), fix the DEV gateway on the host — do not fall back to `ipfs.io` in sandbox demos.

## Primary gateway (production)

Use the main Pinarkive gateway for content pinned to the **global** cluster:

```
https://gateway.pinarkive.com/ipfs/<cid>
```

Replace `<cid>` with your content identifier.

## Secondary gateway

For redundancy, use the public IPFS gateway:

```
https://ipfs.io/ipfs/<cid>
```

## Cluster-specific gateways

| Cluster | Gateway URL |
|---------|-------------|
| **global** | `https://gateway.pinarkive.com/ipfs/<cid>` |
| **eu** | `https://eu1.gateway.pinarkive.com/ipfs/<cid>` |
| **na** | `https://na1.gateway.pinarkive.com/ipfs/<cid>` |
| **us** | `https://us1.gateway.pinarkive.com/ipfs/<cid>` |
| **de** | `https://de1.gateway.pinarkive.com/ipfs/<cid>` |

## Usage in apps

Build the URL from the `cid` returned by the [upload](/api-reference/post-files) or [pin](/api-reference/post-pin) API. You can also get gateway bases from [GET /users/me/clusters](/api-reference/get-clusters):

```javascript
const cid = response.cid
const url = `https://gateway.pinarkive.com/ipfs/${cid}`
```

See [Clusters](/concepts/clusters) for more on regions.
